# 能力描述

> 本文只讲**这个能力本身**：它是什么、吃什么、吐什么、边界在哪、怎么算合格。
> **主项目是什么** → `references/project.md`。两者互不越界。

## 1. 一句话

把一块**任意 HTML/CSS/JS 画面**，收束成一份**受约束的小屏面板素材**，
并给出**可判定的合规结论**。

## 2. 输入 / 输出

| | 内容 |
|---|---|
| **输入** | ① 画面需求（要显示什么、分辨率、风格、底图方式、**交付形态：本地 / 在线**）；② 可选：一份已有素材（做校验） |
| **输出** | ① 一个**单文件 `.html` 素材**（含内嵌产物清单块）；② 一份**自检结论**（人读 / JSON / 退出码）；在线形态另加**托管地址**与一句「取不到时显示什么」 |

## 3. 边界

| | |
|---|---|
| ✅ **做** | **生成**素材（本地 / 在线两种形态）· **验证**素材（静态契约 + 运行时行为）· **定义并校验产物格式** |
| ❌ **不做** | 给别人看的预览图 / 渲染出图（交给别的环节） |
| ✅ **做** | **自截图自检**：模型有视觉能力时用 `scripts/screenshot.py` 出图给自己看，这是判闸门 4 的手段，不是交付物 |
| ❌ **不做** | 抓帧、差分、协议、下发、设备交互（那是主项目的事，见 `project.md`） |
| ❌ **不做** | 普通网页 / 桌面端界面 |
| ❌ **不做** | **部署 / 托管本身** —— 在线素材只负责「页面可托管 + 自己取数」，往哪放、怎么发版是用户的事（步骤见 `references/online_hosting.md`） |

## 4. 能力级验收判据

一份素材**合格**，当且仅当：

1. **形态**合规 —— 契约 C1–C8 全过（本地；在线形态另加 C9–C12，见 `references/contract.md` §8）
2. **产物可抓取** —— 内嵌清单块齐全自洽（`references/output_format.md`）
3. **机器可判项**全过 —— 自检 A1–A15 / B1–B7 无 FAIL；在线形态另查 A16–A19（`--mode online`，见 `references/self_check_gates.md`）
4. **看得见的问题**全过 —— 闸门 4 的内容与主题一致性；模型有视觉能力就**自己截图判**（`scripts/screenshot.py`），没有就明说未判（同上）
5. **约束渲染条件**在**目标画布**下成立 —— 不是"在 320×240 下成立"，而是
   **在调用方声明的 W×H 下成立**（判据见下）

## 5. 「满足约束渲染条件」怎么判

"约束渲染条件"指画面必须在这些硬条件下仍然成立。判据**全部可机检**（`--size` 传什么就按什么判）：

| 约束 | 判据 | 谁判 |
|---|---|---|
| 视口锁死 `W×H` 贴左上 | 样式表最前的规则块**同时**声明 width+height，且推断值 = 声明值 | A1 A2 A3 |
| 坐标整数像素 | 内联 `left/top/width/height` 无半像素 | A9 |
| 元素不越界 | 每个元素内容包围盒 ≤ `W×H`（按 `--size` 的真实画布） | A11 **B4** |
| 低分辨率可读 | 字号 ≥11px（中文一律 ≥11px）· 文字对比度 ≥6:1（硬线 4.5:1） | **B6 B7** |
| 文字不互相压 | 文字×文字基线框一挨上即算重叠 | **B5** |
| 每帧变化面积小 | ≤ 画布 10%（唯一性能杠杆） | 自查（闸门 3.7） |
| 无 GPU 合成依赖 | 不得依赖 `backdrop-filter` 一类在隐藏/离屏 WebView2 下不保证生效的效果 | 闸门 4 + 风格目录 |
| RGB565 色深 | 避免 1px 浅色细线（会被色深吃掉） | 闸门 4 + 风格目录 |

> **换尺寸不改判据**：上表的判据只依赖调用方声明的 `W×H`，不写死任何具体分辨率 ——
> 这是「在不同场景下都满足约束渲染条件」的可判定含义。
